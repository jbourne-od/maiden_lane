# SDD ledger — plan: docs/superpowers/plans/2026-08-17-durable-plan-storage.md
Setup: branch `claude/durable-plan-storage` off `main` at 9fc3ca0 (PR #9 merged); baseline `make verify` passed.
Blocker established before planning, by inspection rather than assumption: ports.PlanRecord holds a semantic.Compilation, which cannot be persisted because all its fields are private and Compile is the only way to obtain one. The kernel has NO decoder at all — grep for From*Bytes/Decode/Parse/Unmarshal across internal/semantic returns nothing, every canonical encoder being one-way by design. The in-memory adapter hid this entirely by storing live Go values, and the port's own doc comment instructed a durable adapter to "rehydrate through the kernel's constructors", which is not followable because no constructor accepts bytes.
Resolution keeps the kernel one-way: the record carries an immutable persistable compilation input, the adapter owns its own encoding, and a read RECOMPILES and requires the resulting PlanID and CompilationInputDigest to equal what was stored. A corrupted, truncated, tampered, or silently re-encoded row therefore cannot produce a plan claiming the stored identity, so storage is structurally unable to lie and the serialization format needs no trust.
Owner decisions ratified 2026-08-17: (1) PostgreSQL is the default store rather than something to abstract away — database agnosticism costs the features worth having and buys optionality never exercised, while internal/ports exists to keep I/O out of the domain and make adapters testable, not to enable vendor swapping. (2) Blobs stay in PostgreSQL; S3 deferred until size or cost justifies a second system, since one transactional store removes the dual-write class of bug. (3) pgvector out of scope: a deterministic transformation engine has no retrieval step.
Owner-ratified storage constraint with a project-specific reason: NO identity-bearing value may be stored as jsonb. Postgres jsonb reorders object keys, drops duplicates, and normalizes numeric forms, which for a system whose identity derives from exact canonical bytes is a silent mutation of the recipe — the "JSON is never a canonicalizer" rule reappearing one layer down, where it is much harder to notice because SQL-level filtering of declarations would appear to work. Identity-bearing content is bytea; jsonb is permitted only for operational metadata that is never hashed.
Verification split ratified: `make verify` stays pure Go and must run with no Docker and no database; PostgreSQL adapter tests live behind a separate Docker-gated target mirroring container-check. Substitutability is established by ONE shared port contract suite that both adapters must pass, rather than by asserting the claim in a comment.
Task 1: complete. semantic.CompilationInput added (immutable, private interior, Request() deep-copies, Digest() equals the compilation's own InputDigest, CanonicalBytes() defensively copied), Compilation.Input() exposes it, and cloneCompileRequest lives in the kernel beside the declaration types it copies so a field added to one is handled where it is defined rather than in an adapter that cannot see it. The input is cloned on the way in as well as out, so a caller mutating the request it passed cannot reach the compilation. ports.PlanRecord carries Input; httpapi uses record.Input.Request() and compileRequestFor was deleted. Fresh `make verify` passed.
Task 1 kernel-change justification and safety: this is the first change to internal/semantic since it was declared complete. It adds no import and no meaning — no canonical encoding, no digest, and no artifact identity moves — which was verified by running every frozen golden-vector test plus the Task 10 import-boundary and allowlist tests unchanged. A failed compilation retains its input too, so a caller diagnosing a rejected program can still name it.
Task 1 tests: mutation is attempted through every reachable path of the returned request (transformation IDs, declared reads, form sources and output slot, aggregate target and required tuple, checkpoints, profile keys and requirement codes, schema entity kinds and field names) and the compilation's plan identity is required to be unchanged, plus a second Request() must be unaffected by mutating the first. Recompiling the retained input must reproduce the identical PlanID, input digest, plan canonical bytes, and every profile identity — which is precisely the property the durable adapter will depend on.
Task 2: complete. internal/ports/storagecontract holds nine behavioural assertions every PlanStore must satisfy: tenant isolation for a shared content-derived identity, a foreign tenant reported byte-identically to an absent one, idempotent put, distinct plans coexisting, incomplete records refused, cancellation honored, concurrency safety, round-trip identity reproduction, and stored records unreachable for mutation. The in-memory adapter passes all nine unchanged; its own test file now keeps only genuinely adapter-specific properties (a fresh store is empty, two stores share no state, and an explicit assertion that this adapter is NOT durable so the limitation cannot be mistaken for persistence).
Task 2 design decision: the suite imports NO fixture package and builds its own minimal domain-free compilation from internal/semantic alone. Two reasons. Storage behaviour has nothing to do with any particular rule, so coupling them would let a storage test fail for a reason unrelated to storage. And a non-test package under internal/ports importing the team-HOS fixture would trip the fixture-isolation walk extended in the previous slice — the walk caught the design question before it became a defect.
Task 2 verified negatively, which is the point of the task: a deliberately broken adapter (ignores tenant, ignores cancellation, no validation) was run against the suite and REJECTED on four counts — tenant leakage, existence disclosure of a foreign artifact, missing record validation, and ignored cancellation. A contract suite only ever run against a passing implementation proves nothing; this one has teeth before the durable adapter depends on it. Probe removed after verification.
Task 2 note for Task 3: `round trip reproduces the stored identities` passes trivially for the in-memory adapter because it stores live values. That is deliberate rather than a weakness — the assertion is written so a durable adapter cannot satisfy it by accident, and a lossy or re-encoding round trip will fail there rather than silently returning a plan under an identity it did not produce.
