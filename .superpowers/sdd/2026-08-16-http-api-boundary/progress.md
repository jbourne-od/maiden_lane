Task 4 owner decisions ratified 2026-08-16: (1) unknown JSON members are REJECTED, not ignored. Rationale recorded in code: a misspelled member would otherwise be silently dropped and the run would proceed over inputs the client did not intend, producing a valid artifact that is quietly wrong. The tradeoff is stated beside it — new optional members must reach the contract before any client may send them. (2) GET /v1/plans echoes the declarations; POST does not. The deciding argument was that the trace allowlist is three identities plus closed tokens and metrics are bounded enums, so operational telemetry is STRUCTURALLY incapable of ever carrying declarations; an operator landing on a PlanID from a trace has no other way to ask what the plan says. Crucially the projection is derived from the compiled plan via CompiledTransformation.Declaration(), not from a stored copy of the request, so it shows what the compiler accepted in canonical order — where that differs from what was sent, the difference is the canonicalization, which is usually the thing being looked for.
Task 4 load-bearing proof: TestStateFromWireMatchesTheKernelConstructedDigest asserts a state built from JSON has a StateDigest byte-identical to the same state built directly through the kernel. Every downstream identity derives from that digest, so a divergence would silently fork the whole artifact graph. TestWireOrderingDoesNotChangeIdentity proves JSON array order is not semantic. TestPlanProjectionRoundTripsThroughTheCompiler re-translates the projected declarations and recompiles them, requiring the identical PlanID: a projection that did not round-trip would be describing a plan that does not exist. TestPackageNeverConstructsADigest scans this package's production source and fails on a `"sha256:` literal or a crypto/sha256 import, so identities can only be projected, never assembled.
Task 4 decisions: entity identities are derived from lineage plus canonical source key rather than accepted from clients, so a client cannot forge or collide one; proved by showing a lineage change invalidates every prior identity. An absent world becomes the real versioned empty world rather than a zero value, since the empty world participates in run identity. Unknown value kinds, kind/payload disagreement, multiple payloads, unratified world reference kinds, invalid executor identities, and unratified provenance policies are all refused rather than coerced.
Task 4 generator change: always-prefix-enum-values was enabled in both codegen configs. Without it the contract's value kinds generated as bare `String`, `Int64`, and `Atom`, polluting the package namespace and guaranteed to collide once a second enum reuses a value name such as `Ready`. Contract and generated code reverified in sync.
Task 4 documented limitation (recorded, not hidden): encoding/json matches member names case-insensitively, so DisallowUnknownFields does NOT reject `rootkey` for `rootKey`. A first test asserted it would; the assertion was wrong about Go, not about the code. The member still maps to the field the client intended, so no data is dropped and no artifact is silently wrong, which is the risk strict decoding exists to prevent. What it does mean is that this server accepts casings the contract does not declare, and clients must not depend on them. TestStrictDecodingIsCaseInsensitiveForKnownMembers records the behavior explicitly so the gap is known rather than discovered later; closing it would require decoding into raw members and comparing keys exactly, which is not worth the reflection cost for a mismatch that preserves intent.

Task 5/6 REVIEW FIXES (owner review of PR #9, 2026-08-16). Two correctness findings, both gating merge, plus a test-honesty finding and a contract audit. All addressed.
Finding 1 — mutable retained CompileRequest. Correct and mine. ports.PlanRecord had gained a semantic.CompileRequest, which unlike Schema and Compilation is an ordinary authoring structure of exported slices and pointer-bearing declarations, so storing it handed every caller a mutable alias into the store and silently falsified the memory adapter's comment that no defensive copy was needed. Fixed by REMOVING the field rather than by cloning it. The reviewer's own preferred direction was an immutable value rather than teaching each adapter to deep-copy, and removal achieves that without a kernel change: the kernel's accessors (Plan.Transformations, CompiledTransformation.Declaration, Plan.Checkpoints, CompiledProfile.Declaration, Schema.Declaration) already deep-clone, including the Form/Aggregate pointer payloads, so compileRequestFor rebuilds a fresh request from the immutable Compilation on each call and shares nothing with storage. PlanRecord again holds only immutable kernel values, which makes the port's stated promise true rather than merely documented, and every future adapter inherits it with no deep-copy knowledge. Cloning in the adapter was rejected precisely because it would have required ports or the adapter to mirror the kernel's type structure, where a new field added upstream would silently reintroduce aliasing.
Finding 2 — absent-plan integrity hole. Correct and mine. The check was `present && plan.ID() != record.PlanID`, so a run reporting SpineInvalidPlan with no plan and a nil error would sail past it and return 200 invalid_plan for a plan that /v1/plans had already accepted and stored. Now `!present || plan.ID() != record.PlanID` yields internal-error. Once an accepted PlanID exists, an execution that cannot reproduce it is an integrity failure on the server side, never a verdict about the caller's request. Regression test drives it through a stub SpineRunner returning an empty result, and additionally asserts the answer is not reported as invalid client input.
Finding 3 — test lie. Correct. TestEveryVersionedRouteRejectsAMalformedTenant claimed to walk registered routes while naming three in a table, and its len(operations) != 3 guard only proved nobody edited the table. It now enumerates the real routes via chi.Walk over the router, filters the /v1 prefix, substitutes path parameters, and fatals if the walk discovers nothing. Verified empirically that the walk sees all five registered routes and selects the three versioned ones, so a fourth is covered automatically.
Finding 4 — advertised-but-unpopulated Execution.inputID, worldID, journalPrefixDigest. Resolved by POPULATING rather than deferring or removing, because the data existed and the fields are genuine replay pins: app.SpineResult gained InputID, WorldID, and JournalPrefixDigest accessors, and spineRun retains the binding so the accepted-history prefix digest can be computed for both the success and retained-frontier paths. Tested that every advertised identity is populated for both fixture variants including the rejected one, and that a one-transition history and a two-transition history do not share a prefix digest. This was scheduled for Task 7 by the reviewer, but leaving three known-false promises in a merged contract is the same defect just removed from SemanticFailure.rule, so it was fixed before merge.
Task 7 carries forward from this review: a small hostile-wire smoke corpus. The reviewer's diagnosis of the `{}` defect is sharper than the original ledger note — typed test construction had made an entire class of syntactically valid but semantically uncanonicalizable wire documents hard to express by accident, and running the binary broke through that abstraction. The lesson is not that unit tests are untrustworthy but that a typed harness cannot easily reach that class, so Task 7 keeps a raw-bytes corpus rather than more typed happy-path handler tests.
